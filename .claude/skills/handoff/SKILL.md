# 작업 인계

대화 맥락이 없는 다음 세션이 저장소만 보고 이어 가도록 작업 상태를 인계 문서와 브랜치로 옮긴다. 진행 장부(`.superpowers/sdd/`), auto-memory, 커밋하지 않은 `docs/superpowers/`는 이 PC에만 있으므로, 이어 갈 때 필요한 내용은 모두 인계 문서에 적는다.

## 마무리 갈래

### 1. 돌고 있는 작업 멈추기

- 서브에이전트, 백그라운드 Bash, Monitor, 워크플로우를 `TaskStop`으로 멈춘다. 멈춘 작업이 작업 트리에 남긴 변경은 2단계에서 가른다.
- 기기를 쓰던 작업은 멈추고 그 작업이 바꾼 기기 상태(테스트용으로 켠 서비스·설정)를 되돌린다. 기기 순서를 조율하던 세션에는 2단계 계측 테스트까지 마친 뒤 기기를 놓았다고 `SendMessage`로 알린다.

### 2. 커밋하지 않은 변경 가르기

`git status --short`와 `git diff HEAD`로 변경을 모아 변경 단위마다 가른다.

| 상태 | 처리 |
|:---|:---|
| 관련 테스트(바뀐 코드의 유닛 테스트, 화면을 바꿨으면 그 계측 테스트)가 통과 | `commit` 스킬로 성격별 커밋. 코드 검토를 거치지 않았으므로 인계 문서에 "검토 전"으로 표시하고, 남은 일 맨 앞에 그 커밋들의 검토를 넣는다 |
| 테스트가 실패하거나 구현이 덜 됨 | 커밋하지 않고 패치로 저장한 뒤 작업 트리에서 되돌린다. 무엇이 덜 됐고 무엇이 실패했는지 인계 문서에 적는다 |

```bash
git add -N <untracked 새 파일>     # intent-to-add로 올려야 git diff HEAD에 나온다
git diff --binary HEAD -- <파일들> > docs/superpowers/handoff/<YYYY-MM-DD>-<주제>-wip.patch
git restore --source=HEAD --staged --worktree -- <파일들>   # HEAD에 없는 새 파일은 지워진다
git apply --check docs/superpowers/handoff/<YYYY-MM-DD>-<주제>-wip.patch   # 되돌린 트리에 다시 적용되는지
```

### 3. 인계 문서 쓰기

경로는 `docs/superpowers/handoff/<YYYY-MM-DD>-<주제>-handoff.md`이고, 주제는 브랜치 주제(`feature/assistant-tasks`면 `assistant-tasks`)다. 같은 브랜치에 앞서 쓴 인계 문서가 있으면 새로 만들지 않고 그 문서를 지금 상태로 고친다.

```markdown
# <작업 이름> 인계 (<YYYY-MM-DD> 중단)

## 기본 정보
- 브랜치: `<브랜치>` (push한 원격 브랜치)
- 워크트리: `.claude/worktrees/<주제>`
- 시작 HEAD(스쿼시 범위의 시작): `<전체 해시>`
- 현재 HEAD: `<해시> <제목>`, 그 위에 이 문서를 담은 문서 커밋 하나
- 설계·계획: `<경로>`
- 작업 방식: <super-flow, 서브에이전트 구성 등>
- 사용자 지시 원문: "<작업을 맡긴 지시>", "<이 인계를 지시한 문장>" (아직 끝나지 않은 지시 표시)

## 문서 커밋 주의
- `docs/superpowers/`는 원래 커밋하지 않는다. 다른 PC에서 이어 가도록 문서를 임시 커밋 하나로 넣었다.
- 스쿼시·머지 때 이 커밋은 결과에서 빼고 파일은 작업 트리에 남긴다(`squash` 스킬).

## 단계별 상태
- [x] <끝난 단계> (`<해시>`)
- [ ] <진행 중인 단계>
  - [x] <끝난 태스크> (`<해시>`, 검토 전)
  - [ ] <남은 태스크>

## 남은 일
1. <대상 파일·함수, 고칠 내용, 추가할 테스트, 확인 명령>

## 검증 현황
- 돌린 것: <명령, 대상, 건수, 결과, 기준 HEAD>
- 확인하지 못한 것: <무엇, 이유, 확인할 수 있는 조건>

## 이어서 할 때의 환경 규칙

## 정해 둔 판단
각 줄은 판단, 이유, 틀리면 생기는 일 순서다.

## <못 드린 산출물> 초안
```

- 시작 HEAD는 설계 문서에 적힌 값을 쓰고, 없으면 `git merge-base HEAD release`다.
- 남은 일은 다음 세션이 다시 조사하지 않고 그대로 실행할 수 있게 쓴다. 진행 장부(`.superpowers/sdd/*/progress.md` 등)의 판정과 보류한 검토 지적은 남은 일·정해 둔 판단으로 옮긴다.
- 환경 규칙에는 저장소 규칙(`CLAUDE.md`·스킬)을 베끼지 않고, 이 작업에 걸린 기기·계정·개인 데이터 제약, 이 작업에 걸리는 auto-memory 규칙(다른 PC에는 없다), 규칙에 어긋나 스쿼시 때 바로잡을 커밋을 적는다.
- 정해 둔 판단 중 사용자가 정한 것은 `사용자 결정`, 사용자가 정해야 하는 것은 `사용자 결정 필요`로 표시한다.
- 마지막 절은 사용자가 요청했지만 아직 드리지 못한 산출물(리뷰 가이드 등)의 초안이며, 없으면 뺀다.

### 4. 문서 커밋

이 작업의 설계·계획·인계 문서와 wip.patch를 `기타:` 커밋 하나로 넣는다. `docs/` 아래 다른 작업의 문서는 넣지 않는다. 본문 문장은 이 커밋을 결과에서 빼야 한다는 표지이므로 그대로 쓴다.

```bash
git add <문서들>
git commit -m "$(cat <<'EOF'
기타: <작업> 설계, 계획, 작업 인계 문서 추가

- 다른 PC에서 이어 작업하기 위한 임시 커밋이며 스쿼시·머지 때 결과에서 뺌
EOF
)" -- <문서들>
```

나머지 형식(귀속 라인, `git show --stat HEAD` 확인)은 `commit` 스킬을 따른다.

### 5. push

- 인계 요청은 그 자체로 `CLAUDE.md`의 명시적 push 지시이므로 묻지 않고 `git push -u origin <브랜치>`를 실행한다. 요청에 push나 다른 PC가 언급되지 않아도 같다. (금지: 같은 PC의 다음 세션만 말했다고 push를 건너뜀, 허용: 어떤 인계든 문서 커밋 뒤 push)
- 원격이 앞서 있어 거부되면 force push하지 않고 멈춰 알린다. 다른 PC가 그 사이 push한 커밋이다.

### 6. 보고

- 이번에 만든 커밋(해시와 제목)과 push 결과(원격 브랜치, 거부됐으면 그 사실)
- 남은 일 요약과 이어받는 방법(다른 PC에서 "인계 문서 보고 이어서")
- 응답 맨 끝에 인계 문서 경로

## 이어받기 갈래

1. **워크트리 준비**: 기본 체크아웃에서 `git fetch origin` 뒤 `.claude/references/orca-environment.md` 워크트리 절의 기존 브랜치 방식을 따른다.
    - 이 PC에 그 브랜치의 워크트리가 있으면 `EnterWorktree(path)`로 들어가 `git merge --ff-only origin/<브랜치>`로 맞춘다. 거부되면 두 PC가 따로 커밋한 것이므로 멈추고 알린다.
    - 없으면 `git -C <기본 체크아웃> worktree add .claude/worktrees/<주제> <브랜치>`로 만든다. 로컬 브랜치가 없어도 `origin/<브랜치>`를 추적하는 브랜치가 생긴다. 로컬 브랜치가 원격보다 뒤처져 있었으면 위와 같이 fast-forward로 맞춘다.
    - 새로 만든 워크트리에는 기본 체크아웃의 `local.properties`를 복사하고 `EnterWorktree(path)`로 옮긴다.
2. **문서 읽기**: 그 브랜치의 인계 문서(`docs/superpowers/handoff/`)와 문서가 가리키는 설계·계획을 읽는다. 환경 규칙과 정해 둔 판단은 이 세션의 전제로 따른다.
3. **wip.patch**: 문서에 패치가 있으면 `git apply --check`로 확인한다. 남은 일이 그 패치를 이어 쓰라고 하고 충돌이 없으면 적용하고, 아니면 적용하지 않고 구현 참고로만 쓴다. 적용 여부는 보고에 적는다.
4. **진행**: 남은 일을 순서대로 진행하며 인계 문서의 체크박스를 작업 트리에서 갱신한다. 다시 멈출 때는 마무리 갈래를 같은 인계 문서로 반복한다.
5. **끝낼 때**: 스쿼시 범위는 인계 문서의 시작 HEAD부터다. 인계 문서 커밋은 어느 그룹에도 넣지 않고 파일은 작업 트리에 남긴다(`squash` 스킬).
