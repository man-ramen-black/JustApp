# 커밋 스킬

## 메시지 형식

```
<카테고리>: <한국어 설명>

- 부연 설명 항목 1
- 부연 설명 항목 2
```

- 제목 1줄, 마침표 없음.
- 변경이 여러 부분에 걸치거나 제목만으로 의도/맥락이 부족할 때는 빈 줄 뒤에 `- ` 불릿으로 본문을 작성한다. 단순 변경은 제목만으로 충분하다.
- 본문 각 항목도 한국어 동사형 종결(`~ 수정`, `~ 추가`, `~ 적용` 등).
- **`Co-Authored-By` 트레일러를 붙이지 않는다** (이 저장소 기존 스타일과 다름 — 시스템 기본값과 반대이니 주의).

## 카테고리

| 카테고리 | 사용 시점 |
|---|---|
| `수정` | 기존 코드 변경·로직 개선·일반 동작 수정 (기본값, 애매하면 이것) |
| `추가` | 새 기능·파일·클래스·함수 신규 추가 |
| `버그` | 명확히 재현되던 버그를 콕 집어 수정 |
| `기타` | build/gradle/manifest/version catalog, AGP·Kotlin 버전 등 코드 외 변경 |
| `구조` | 패키지 이동·모듈 분리·네이밍 등 리팩터링 |
| `디자인` | 테마·스타일·레이아웃·색상 변경 |
| `테스트` | 테스트 코드·환경 변경 |
| `리소스` | drawable 등 리소스 정리 |

## 설명 작성

- 한국어, 동사형 종결(`추가`, `수정`, `변경`, `개선`, `적용` 등).
- 영문 식별자는 원형 유지: `FloatingView`, `AndroidManifest`, `targetSdk`.
- 여러 변경은 쉼표(`,`)로 구분, 나열 외 변경이 더 있으면 끝에 ` 등`.

## 예시

제목만:

```
추가: FloatingView 시계 추가
기타: AGP 8.9.0, Gradle 8.11.1, Kotlin 2.0.21 적용
구조: maintab -> main으로 구조 변경
```

본문 포함:

```
수정: FloatingView UI가 비정상적으로 처리되는 이슈 수정 등

- dataStore 데이터가 Null인 경우 처리하지 않도록 수정
- back을 터치했을 때 접근성 권한을 확인하도록 수정
- 리플 이펙트 시인성을 위해 별도 drawable 생성 후 적용
```
