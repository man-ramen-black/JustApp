# 커밋 스킬

## 분할·합침

- 커밋 요청을 받으면 변경 내용을 먼저 살펴, 독립적인 관심사가 섞여 있으면 여러 커밋으로 나누고 하나의 작업이면 합쳐서 커밋한다.
- 같은 기능·버그·리팩터링에 속하면 한 커밋으로 합치고, 성격이 다른 변경(예: 기능 수정 + 무관한 문서·설정)이 섞이면 나눈다.
- 나눌 때는 각 커밋이 독립적으로 의미를 갖도록 해당 변경의 파일만 스테이징한 뒤 커밋한다.
- 규칙·스킬 문서(`CLAUDE.md`, `.claude/**`) 수정은 주제가 달라도 `기타` 한 커밋으로 묶되, 프로덕션 코드·테스트 코드 변경과는 분리한다.
- 스펙·플랜 문서(`docs/superpowers/`)는 커밋하지 않는다.

## 메시지 형식

```
<카테고리>: <한국어 설명>

- 부연 설명 항목 1
- 부연 설명 항목 2
```

- 제목 1줄, 마침표 없음.
- 변경이 여러 부분에 걸치거나 제목만으로 의도/맥락이 부족할 때는 빈 줄 뒤에 `- ` 불릿으로 본문을 작성한다. 단순 변경은 제목만으로 충분하다.
- 본문 각 항목도 한국어 동사형 종결(`~ 수정`, `~ 추가`, `~ 적용` 등).

## 카테고리

| 카테고리 | 사용 시점 |
|---|---|
| `수정` | 기존 코드 변경·로직 개선·일반 동작 수정 (기본값, 애매하면 이것) |
| `추가` | 새 기능·파일·클래스·함수 신규 추가 |
| `버그` | 명확히 재현되던 버그를 콕 집어 수정 |
| `기타` | build/gradle/manifest/version catalog, AGP·Kotlin 버전, `CLAUDE.md`·`.claude/**` 규칙·스킬 등 코드 외 변경 |
| `구조` | 패키지 이동·모듈 분리·네이밍 등 리팩터링 |
| `디자인` | 테마·스타일·레이아웃·색상 변경 |
| `테스트` | 테스트 코드·환경 변경 |
| `리소스` | drawable 등 리소스 정리 |

## 설명 작성

- 한국어, 동사형 종결(`추가`, `수정`, `변경`, `개선`, `적용` 등).
- 영문 식별자는 원형 유지: `FloatingView`, `AndroidManifest`, `targetSdk`.
- 여러 변경은 쉼표(`,`)로 구분, 나열 외 변경이 더 있으면 끝에 ` 등`.
- `·` 같은 특수문자는 사용하지 않고 쉼표 등 일반 문장부호만 사용.
- 평서형(`~한다`), `~음` 종결(`고침`, `옮김`), 과거형으로 끝맺지 않는다.
- 제목을 출처(`회고 반영 -`, `리뷰 반영 -`)로 시작하거나 대시·콜론 뒤에 부제를 붙이지 않는다. 무엇이 바뀌었는지만 쓰고 세부는 본문에 둔다.
- 형식의 근거는 이 문서다. 최근 커밋은 같은 대상을 이미 건드렸는지 확인하는 용도로만 읽고 문체 근거로 삼지 않는다.

## 커밋 실행

1. `git status --short`와 `git diff HEAD`로 변경을 수집한다. 신규 파일은 `git diff HEAD`에 나오지 않으므로 `git ls-files --others --exclude-standard`로 따로 확인한다.
2. 대상 파일만 명시적으로 스테이징한다. `git add -A`, `git add .`, 디렉터리 지정은 쓰지 않는다(진단용 임시 수정이나 다른 세션의 편집이 함께 실린다). 파일 목록을 셸 변수에 담아 넘기지 않고 매번 그대로 나열한다(zsh는 변수 확장 시 단어를 나누지 않는다).
3. 커밋도 pathspec으로 대상 파일을 한정한다. pathspec이 없으면 미리 스테이징돼 있던 다른 파일까지 함께 커밋된다.
   ```
   git commit -m "$(cat <<'EOF'
   추가: FloatingView 시계 추가

   - FloatingClockView 신규 추가
   EOF
   )" -- <파일1> <파일2>
   ```
4. `git show --stat HEAD`로 커밋된 파일이 의도한 대상과 일치하는지 확인한다. 어긋났으면 `git reset --soft HEAD~1` 후 다시 커밋한다.

- 세션이 지정한 귀속 라인(`Co-Authored-By` 등)이 있으면 본문 맨 끝에 붙인다.
- `--amend`, `--no-verify`는 쓰지 않는다. hook이 실패하면 원인을 고친 뒤 새 커밋으로 진행한다.
- 여러 커밋을 합치는 작업은 `squash` 스킬을 따른다.

## 예시

제목만:

```
추가: FloatingView 시계 추가
기타: AGP 8.9.0, Gradle 8.11.1, Kotlin 2.0.21 적용
구조: maintab -> main으로 구조 변경
```

본문 포함:

```
수정: FloatingView UI가 비정상적으로 처리되는 이슈 수정 등

- dataStore 데이터가 Null인 경우 처리하지 않도록 수정
- back을 터치했을 때 접근성 권한을 확인하도록 수정
- 리플 이펙트 시인성을 위해 별도 drawable 생성 후 적용
```
